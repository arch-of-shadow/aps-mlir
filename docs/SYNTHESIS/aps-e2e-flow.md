# End-to-end synthesis pipeline

[tools/aps-opt/main.cc](../../tools/aps-opt/main.cc) defines the production
pipeline. Use it to establish pass order and defaults. `aps-opt` is the separate
MLIR pass driver for isolated transformations.

## Driver interface

```sh
pixi run build/tools/aps-opt/aps-e2e \
  -i build/input.mlir -o build/design.sv --export sv \
  --clock 4 --resource examples/resource_ihp130.json \
  --dump-scheduled-tor build/design.tor.mlir \
  --dump-cmt2 build/design.cmt2.mlir
```

`build/input.mlir` must already contain functional APS input, generated by the
CADL frontend or the ScaleISA adapter.

| Option | Contract |
|---|---|
| `-i`, `--input` | Required MLIR input path |
| `-o`, `--output` | Output file; defaults to standard output |
| `--export` | `scheduled-tor`, `cmt2` (default), `firrtl`, or `sv` |
| `--clock` | Scheduling period in ns; default 6 |
| `--resource` | Scheduling resources; default `examples/resource_ihp130.json` |
| `--dump-scheduled-tor` | Write selected TOR before temporal splitting |
| `--dump-cmt2` | Write CMT2 before FIRRTL/SV export |
| `--print-ir-after-all` | Print pass results to standard error |
| `--interface-config` | Apply platform JSON and generate a Chipyard YAML sidecar |
| `--chipyard-config` | Override the sidecar path |

Platform configuration requires `--export sv` and a named output file. The default
sidecar replaces the RTL filename extension with `.chipyard.yaml`.
See [integration](../ARCHITECTURE/README.md).

## Stages and invariants

1. **Functional preparation.** Move register reads to entry, expose scratchpad
   operations as memrefs, selectively raise SCF loops to affine, and infer affine
   memory maps. Canonicalization cleans up between transformations.
2. **Scheduled baseline.** Add default burst partitioning, build the memory map,
   unroll, partition arrays, restore APS accesses, and bind functional memory to
   modeled interfaces. Promote singleton storage, simplify arithmetic, lower
   affine loops, balance expressions, convert to TOR, order memory transactions,
   and run TOR scheduling.
3. **Scratchpad-elision trials.** Analyze eligible staged buffers, clone functional
   IR, rewrite a candidate, and run the actual scheduling pipeline again. Accept
   only supported schedules with non-increasing invocation cycles and loop IIs
   that also respect scalar inflight capacity. Otherwise retain the baseline.
4. **Temporal/CMT2 lowering.** Split architectural memory operations into
   issue/wait pairs, build the time graph, duplicate eligible scratchpad loads,
   canonicalize, optimize storage, and run `aps-to-cmt2`.
5. **Export.** CMT2 export stops here. FIRRTL export runs CMT2 lowering. SV export
   additionally runs the CIRCT firtool preprocessing, FIRRTL-to-HW, HW-to-SV, and
   Verilog export pipelines in process.

The `scheduled-tor` export and dump show the selected result of elision trials.
They precede issue/wait splitting. The CMT2 dump includes the generated hierarchy.
Use [HLS](hls-passes.md) for transformation details and
[CMT2 lowering](aps-to-cmt2-transfer-model.md) for execution semantics.

## Debugging

```sh
pixi run build/tools/aps-opt/aps-e2e \
  -i build/input.mlir --export cmt2 -o build/design.cmt2.mlir \
  --print-ir-after-all 2> build/passes.log
```

Locate the first failing transformation and inspect its input. Typical boundaries
are unsupported frontend constructs, illegal memory lengths/layouts, unsupported
pipeline bodies, missing resource entries, and stale floating-point timing.
The module library manifest is loaded relative to the repository root at
`circt/lib/Dialect/Cmt2/ModuleLibrary/manifest.yaml`.

For a pass-level reproduction, query registered options rather than reconstructing
an old end-to-end pass list:

```sh
pixi run build/tools/aps-opt/aps-opt --help
```
